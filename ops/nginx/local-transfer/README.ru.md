# Локальный импорт образа NGINX

Первый этап: Woodpecker собирает и тестирует образ от ac-ci-builder, экспортирует docker-archive, root-команда импортирует его в rootful Podman. GHCR не нужен. Работающий nginx1 не останавливается, не пересоздаётся и не перезагружается. Это ещё не production deploy.

## Установка на VPS

Из корня репозитория nginx_container:

```sh
sudo sh ops/nginx/local-transfer/install.sh
```

Зависимости: Python >=3.9, sudo/visudo, Podman /usr/local/bin/podman. Пользователь ac-ci-builder должен иметь UID 1001. Существующая директория /var/lib/ac-nginx должна принадлежать root без права записи для группы и остальных пользователей.

Установщик ставит root-owned /usr/local/sbin/ac-nginx-import и правило sudoers только для него. Создаёт /var/spool/ac-nginx/inbox для архивов сборщика и закрытую директорию /var/lib/ac-nginx/imports для обработки и квитанций. Supervisor и контейнеры не меняются.

Добавьте шаг из woodpecker-step.yaml в конец существующего списка steps в .woodpecker.yaml, после test. Не заменяйте весь pipeline этим фрагментом. Не добавляйте failure/always-условия: импорт должен выполняться только после успешных проверок. Сохраните фильтр событий push/manual, ветки main и backend local.

Закоммитьте ops/nginx/local-transfer и изменение .woodpecker.yaml. После сборки ожидается IMPORT_OK с тегом localhost/nginx-container:<полный SHA> и image ID. Проверьте на сервере, подставив SHA успешной сборки:

```sh
sudo podman image inspect localhost/nginx-container:FULL_COMMIT_SHA --format '{{.Id}}'
sudo podman inspect nginx1 --format 'Image={{.Image}} Running={{.State.Running}}'
```

У nginx1 должен остаться прежний image ID: импорт сам по себе его не обновляет. Для следующего этапа потребуется проверка нового образа с production-конфигурацией, управляемая замена и откат.

## Граница полномочий

Все пайплайны с аккаунтом ac-ci-builder смогут вызывать импорт. Это не изоляция по репозиторию. Helper проверяет форму SHA, единственный ожидаемый тег и метку revision, но не доказывает происхождение сборки или прохождение тестов. Root-процесс не выполняет скрипты из checkout или образа. Импорт всё равно передаёт архив привилегированному Podman, поэтому аккаунт и его репозитории должны быть доверенными.

Архив ограничен 1 GiB. Он копируется в закрытую root-директорию, проверяется, затем пересобирается только из manifest.json, конфигурации и слоёв. Произвольные дополнительные теги/metadata не передаются Podman. Совпадение существующего SHA-тега с другим image ID вызывает отказ. Для повторной сборки того же commit с изменившейся базой нужен новый commit, либо отдельное ручное решение администратора; автоматически тег не перезаписывается.

После удачного импорта исходный архив удаляется. При ошибке остаётся /var/spool/ac-nginx/inbox/<SHA>.tar для диагностики; его можно удалить от ac-ci-builder. Образы и квитанции автоматически не очищаются. Во время обработки нужно место примерно под три размера архива и распакованный образ. root helper использует штатную конфигурацию root Podman; предполагается обычное локальное rootful хранилище, уже используемое nginx1.

Код не зависит от systemd. При переходе на Devuan этот импорт остаётся тем же при сохранении путей, пользователя и установки Podman/sudo/Python.
